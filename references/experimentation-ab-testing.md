# 实验设计与 A/B 测试

> A/B 测试的价值不在"跑出一个数字"，在于**它是唯一能廉价获得因果结论的手段**。
> 而这个价值极其脆弱——随机化、分流、指标、停止规则任何一环出问题，因果性立刻消失。

## 一、开始前必须写下的实验方案

**在看到任何数据之前**把下面这些定死，写进文档（用 `assets/experiment-design-doc.md`）。
事后再定义等于自欺欺人。

| 项 | 要求 |
|----|------|
| **假设** | "改成 X 会让 Y 提升，因为 Z"。必须有机制解释，否则显著了也不知道为什么 |
| **主指标（OEC）** | **有且仅有一个**。多个主指标 = 没有主指标 |
| **护栏指标** | 不能变差的底线：崩溃率、延迟、退款率、投诉率 |
| **次要/探索指标** | 明确标注为探索性，其结论只能作为下次实验的假设 |
| **随机化单元** | 用户 / 设备 / 会话 / 请求，见下节 |
| **流量分配** | 各组比例、是否有 holdout |
| **MDE 与样本量** | 最小可检测效应 + 达到 80% power 所需样本量与预计时长 |
| **停止规则** | 跑满多少天/多少样本才看结果。以及什么情况下紧急停止 |
| **分析方法** | 检验方法、是否分层、如何处理异常值 |

## 二、随机化单元：决定了实验的天花板

| 单元 | 适用 | 风险 |
|------|------|------|
| **用户 ID** | 默认首选 | 需要用户已登录；跨设备一致性依赖账号体系 |
| **设备 / Cookie** | 未登录场景 | 同一人多设备会被分到不同组，稀释效应；清缓存后重新分配 |
| **会话** | 只影响单次体验的改动 | 同一用户会看到不同版本，体验不一致；不能测留存类指标 |
| **请求** | 后端性能实验 | 完全不能用于任何用户行为指标 |
| **地区 / 门店** | 有网络效应或线下场景 | 单元数少，统计效力低，需要用 switchback 或合成对照 |

**核心规则**：随机化单元必须**不小于**指标的统计单元。
用会话分流却统计"人均下单数"，会导致同一用户同时贡献两组数据，方差估计全错。

**溢出效应（干扰）**：社交、竞价、共享库存场景中，实验组的行为会影响对照组。
例如实验组更激进地抢券，对照组能抢到的就变少了——测出来的差异会被放大。
处理：按社交簇 / 地理区域整体分流，或用时间切换（switchback）设计。

## 三、分流质量：SRM 是第一道体检

**样本比例不匹配（Sample Ratio Mismatch）**：预期 50/50，实际 50.4/49.6。
看起来很小，但在百万量级下这是统计上不可能的偶然。

```
用卡方检验：python3 scripts/ab_test_calc.py --srm --control 502341 --treatment 497108
p < 0.001 ⇒ 分流有问题，实验结果作废
```

SRM 一旦出现，**整个实验必须废弃重来**，不能"忽略它继续分析"。
因为导致比例失衡的机制（重定向失败、埋点丢失、机器人流量、缓存）几乎一定同时污染了指标。

常见 SRM 成因排查顺序：
1. 实验组代码有 bug 导致部分用户崩溃/未上报（最常见）
2. 分流逻辑的哈希不均匀，或用了有偏的 ID（如自增 ID 取模）
3. 触发时机不同：实验组在页面更靠后的位置才计入曝光
4. 机器人/爬虫流量只命中一侧
5. 重定向或加载耗时差异导致跳出率不同

**A/A 测试**是上线实验平台后的必做项：把用户随机分成两组但给完全相同的体验，
跑一遍看主指标是否显著。如果 A/A 都能跑出显著差异，说明平台有系统性问题。

## 四、峰值窥探：最贵的错误

每天看一眼，一显著就停——这会把实际假阳性率从 5% 推到 **30% 以上**。
原因很直观：随机波动总会在某个时刻越过阈值，你只是在等它越过。

三种正确做法：

| 方法 | 做法 | 代价 |
|------|------|------|
| **固定时长** | 事前定好跑 14 天，中途只看护栏指标，到期才看主指标 | 最简单，最可靠。默认用这个 |
| **序贯检验** | 用 mSPRT / always-valid p 值，允许随时看 | 需要平台支持；相同结论所需样本量更多 |
| **成组序贯** | 事前定 3 个中期分析点，用 O'Brien-Fleming 边界 | 需要提前规划，边界计算复杂 |

**最短运行时长至少一个完整周**（通常两周）。原因：
- 星期几效应：周末和工作日用户结构完全不同
- 新奇效应：新 UI 上线初期点击率虚高，1-2 周后回落
- 首因效应：老用户对变化的抵触也会在初期放大负向

只跑 3 天的实验，测的是"改变本身"，不是"改后的稳态"。

## 五、提高灵敏度：在不加样本的前提下

样本量不够时，与其硬等，不如降低方差：

### CUPED（用实验前数据做协变量校正）
用户在实验前的指标表现是实验期表现的强预测因子。把它作为协变量回归掉，
可以降低 **30-50% 的方差**，等价于样本量翻倍。

```
Y_adjusted = Y - θ × (X_pre - mean(X_pre))
θ = Cov(Y, X_pre) / Var(X_pre)
```

前提：`X_pre` 必须是**实验前**的数据，与分组独立。用实验期数据做协变量会引入偏差。

### 指标变换
- 长尾指标做 winsorize（截至 P99）或对数变换，大幅降低方差
- 用二值化指标（是否下单）替代连续指标（下单金额）——损失信息但方差小得多
- 用"人均"替代"总量"

### 分层抽样 / 事后分层
按已知的高方差维度（新老用户、平台、国家）分层，层内比较后加权合并。

### 触发分析
只统计**实际触发了改动的用户**。给全站 100 万用户分流但只有 5 万人看到改动，
把 95 万无关用户算进来会把效应稀释 20 倍。
注意：触发条件在两组必须完全对称，否则引入选择偏差。

## 六、结果解读：显著只是及格线

拿到结果后按顺序检查：

```
1. SRM 通过了吗？              ← 不通过直接作废
2. 护栏指标有没有恶化？        ← 恶化了即使主指标涨也要慎重
3. 主指标的效应量和 CI 是多少？ ← 不看 p 值，看区间
4. CI 下界是否超过最小可接受效应？
5. 分人群看，效应方向是否一致？ ← 全部为正 vs 一正一负，含义完全不同
6. 效应随时间是否稳定？        ← 只在头几天显著 = 新奇效应
7. 与假设中的机制一致吗？      ← 中间指标动了吗
```

**异质性处理效应**（不同人群效果不同）是最有价值的发现，但也是 p-hacking 重灾区。
规则：分人群分析必须事前声明维度，或明确标为探索性发现，等下次实验专门验证。

**阴性结果同样有价值**，前提是检验力足够。报告写法：
"在 80% 检验力下未检测到超过 0.3pp 的效应，95% CI [-0.1pp, +0.2pp]，
可以认为该改动对转化率无实质影响。"这比"没显著，下一个"有用得多。

## 七、什么时候不该做 A/B 测试

- **样本量根本不够**：日活几百的产品，测 1% 的转化率提升需要跑几年。
  改用定性研究、专家评审、或直接上线观察大幅改动。
- **改动是必须做的**：合规要求、安全修复——测了也不会因为负向就不做。
- **效应量预期极大**：从"完全不能用"到"能用"，不需要统计检验。
- **存在强网络效应且无法整体分流**：双边市场、社交图谱，个体分流的结论会系统性偏离。
- **长期效应与短期效应背离**：广告加载量、推送频率这类，短期指标涨长期留存跌。
  必须配长期 holdout 组（保留 1-5% 用户长期不接受任何新实验）观察累积影响。
- **伦理风险**：涉及价格歧视、健康、金融决策的实验要先过伦理审查。

## 八、实验文化的三个反模式

1. **只上线赢的实验，输的悄悄下线不记录**。
   长期后果是团队高估自己的命中率，且同一个坑反复踩。**所有实验结果都要归档，包括失败的**。
2. **为了让实验"成功"而不断切人群**。
   全量不显著 → 只看新用户 → 只看新用户 iOS → 显著了。这是在制造噪声，不是发现信号。
3. **实验结论不设有效期**。
   两年前测出的最优方案，在用户结构和竞品环境变化后可能已经失效。
   核心策略应定期用 holdout 重新验证。
