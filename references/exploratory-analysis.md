# 探索性数据分析（EDA）

> 目标不是"把数据看一遍"，而是**在建模或下结论之前，找出所有会让结论失效的东西**。
> 大部分错误的分析结论，根源不在方法，在于没搞清楚手上这份数据到底是什么。

## 一、先问清问题，再碰数据

拿到数据就开始画图是最常见的时间浪费。动手前必须确定三件事：

| 要问的 | 为什么关键 | 反例 |
|--------|-----------|------|
| **决策是什么** | 分析要服务于一个具体决策，否则产出无人使用 | "分析下用户数据" → 分析完没人看 |
| **口径是什么** | 同一个词在不同部门含义不同 | "活跃用户"是登录过？还是有行为？7 日还是 30 日？ |
| **什么结论会改变行动** | 如果任何结论都不改变行动，这个分析不该做 | 老板已经决定了，只是要数据背书 |

**反向验证法**：先写出结论的两个版本——"如果 A 成立我们会做 X"、"如果 B 成立我们会做 Y"。
写不出来，说明问题没定义清楚，回去和需求方对齐。

## 二、数据来源尽调（比看数据本身更重要）

在算任何统计量之前，先搞清楚这份数据是怎么来的：

- **生成机制**：谁写入的？埋点、业务库同步、第三方导出、人工填报？人工填报的字段可信度最低。
- **采集时间窗**：包含哪段时间？是否有埋点上线日、口径变更日？变更日前后的数据不能直接拼。
- **是否为全量**：抽样了吗？抽样规则是什么？按用户抽还是按事件抽？
- **过滤链路**：上游做过哪些过滤？很多"干净"的数据是因为异常记录被上游默默丢掉了。
- **延迟与补数**：今天的数据是不是还没到齐？最近 1-3 天的数据通常不完整，直接看会看出"下跌趋势"。

> 分析师最常踩的坑不是算错，而是**在一份被上游污染或截断的数据上算得很对**。

## 三、数据画像：先量化，再看图

用 `scripts/profile_dataset.py` 一次性拿到全局画像，重点关注五类信号：

| 信号 | 含义与处置 |
|------|-----------|
| **常量列** | 唯一值只有 1 个，通常是无效字段或过滤条件的残留，可以直接排除 |
| **高基数列** | 唯一值接近行数，多半是 ID、订单号、时间戳，不能当类别特征 |
| **高缺失列** | 缺失率 >50% 的列要先搞清楚"缺失代表什么"再决定用不用 |
| **零方差数值列** | 全是同一个值或方差极小，进模型只会添噪声 |
| **可疑取值** | `-1`、`9999`、`1900-01-01`、`未知`、空字符串——这些通常是**伪装成正常值的缺失** |

**缺失不是随机的**。判断缺失机制决定处理方式：

- **MCAR**（完全随机缺失）：删除或简单填充影响不大
- **MAR**（依赖其他可观测变量）：可以用其他列建模填充
- **MNAR**（缺失本身携带信息）：**最危险**。例如"收入"字段高收入者更倾向不填。
  这时正确做法是把"是否缺失"单独做成一个特征，而不是填一个均值把信息抹掉。

## 四、单变量：分布形状决定后续一切

对每个关键变量，看的不是均值，而是**形状**：

- **数值型**：直方图 + 箱线图。重点看偏度、双峰、长尾、截断（是否在某个值处被人为切断）。
  长尾数据用均值描述会严重误导——收入、时长、金额几乎都是长尾，用中位数与分位数。
- **类别型**：频次排序。看头部集中度和长尾类别数。类别数 >50 时考虑合并低频类为 "其他"。
- **时间型**：按天/小时聚合看趋势。重点找**断点**（某天突然为 0 或翻倍，通常是埋点或口径变更）
  和**周期性**（周末效应、月末效应）。

**双峰分布几乎总是意味着数据里混了两个群体**。看到双峰先别急着建模，先找出分组变量
（新老用户？两个版本？两个渠道？），分开看往往结论完全不同。

## 五、双变量：相关不等于因果，也不等于有用

- **数值 × 数值**：散点图优先于相关系数。皮尔逊相关只捕捉线性关系，
  一个漂亮的 U 型关系相关系数可能接近 0。数据量大时用抽样散点或六边形分箱图避免糊成一团。
- **类别 × 数值**：分组箱线图。同时看每组的**样本量**——某组只有 3 条记录时它的均值毫无意义。
- **类别 × 类别**：交叉表 + 按行归一化的比例。绝对数量会被大类别主导。

## 六、四个必须主动检查的陷阱

### 1. 辛普森悖论
分组内的趋势与合并后的趋势相反。经典场景：新版本在每个渠道的转化率都更高，
但整体转化率更低——因为新版本流量更多来自低转化渠道。

**防御**：任何整体结论，都要在主要分组维度下再看一遍。至少检查设备、渠道、新老用户三个维度。

### 2. 幸存者偏差
数据里只有"活下来"的样本。分析"高留存用户有什么特征"得出的结论，
往往只是"留下来的人自然会有这些行为"，不能反过来指导拉新。

**防御**：明确样本是怎么进入数据集的，问一句"哪些个体不在这份数据里"。

### 3. 时间泄漏
用了在预测时点尚不可得的信息。最隐蔽的形式是"最终状态字段"——
比如用 `user_status` 判断流失，但这个字段是当前值，不是当时值。

**防御**：给每个字段标注"这个值在决策时点是否已知"。快照表优于状态表。

### 4. 分母陷阱
比率类指标的分母定义变了，比值就没有可比性。"转化率下降"经常是因为分母口径扩大了
（比如把爬虫流量算进来了），而不是分子变差。

**防御**：看比率时永远同时看分子和分母的绝对值走势。

## 七、异常值：先解释，再决定

异常值处理的顺序是**识别 → 解释 → 决策**，绝不能跳过中间那步。

| 类型 | 判断 | 处理 |
|------|------|------|
| 录入错误 | 年龄 200、金额为负、日期在未来 | 修正或剔除，并回溯上游修复 |
| 单位不一致 | 同一列混了元和分、米和厘米 | 统一单位，绝不能当异常值删掉 |
| 真实极端值 | 大客户的订单金额确实是别人的 100 倍 | **保留**。删掉它就是删掉业务真相 |
| 系统性异常 | 某天所有值都异常 | 是事故/活动/埋点故障，标注后单独讨论 |

常用识别方法及适用边界：
- **IQR 法**（超出 Q1-1.5×IQR 或 Q3+1.5×IQR）：分布不必正态，适合大多数场景，默认首选
- **Z-score**（|z| > 3）：只在近似正态时有效，长尾数据会误杀大量正常值
- **业务规则**：最可靠。年龄 ∈ [0,120]、金额 ≥ 0——先用业务约束筛一遍

> 记住：**"统计上异常"不等于"应该删除"**。删除异常值必须留下记录：删了多少条、占比多少、
> 依据是什么。不留记录的清洗等于篡改。

## 八、EDA 的收尾产物

一次合格的 EDA 应该产出三样东西，而不只是一堆图：

1. **数据可信度结论**：这份数据能支撑什么结论、不能支撑什么结论、哪些字段不可用及原因
2. **待验证假设清单**：EDA 发现的模式，标注哪些需要统计检验或实验验证（见
   `statistical-inference.md` 与 `experimentation-ab-testing.md`）
3. **口径备忘**：所有字段的实际含义、过滤条件、时间窗——下次分析直接复用，避免重复踩坑

用 `assets/eda-report-template.md` 组织输出。核心要求是：**任何一个数字都能追溯到它的口径和过滤条件**。
